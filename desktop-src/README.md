# Desktop source tree (Linux)

This directory holds the desktop application as an editable source tree instead of
a sealed `app.asar`. It is produced by extracting the official MiniMax Code
desktop build and is meant for reading, patching, and recompiling the app on
Linux, not for installing it.

For a ready-to-use package, use the builds described in [`../desktop/README.md`](../desktop/README.md)
or download a `.deb` from [Releases](https://github.com/xlzhen-940218/minimax-code-linux-arm64/releases/latest).

## Status

Verified on Debian 13, arm64, with app version 3.1.13 and Electron 42.11.16. The
tree also supports x64, but that combination has not been run here.

The app is unofficial and not published or supported by MiniMax.

This directory is a verbatim snapshot of the shipped bundle, so it is excluded
from `release/public-source.json` and from the text scan in
`scripts/source-inventory.mjs`. `pnpm check:source` runs with or without it; see
`../AGENTS.md` for the reasoning.

## Layout

```
desktop-src/
├── package.json          # npm workspace root: app + vendor packages
├── package-lock.json     # the only lockfile in the tree
├── app/                  # the application itself
│   ├── dist/             # main process and preload bundles (readable ES2020)
│   ├── out/              # renderer assets (Next.js static export)
│   ├── public/           # static files served by the protocol handler
│   └── package.json      # pinned runtime dependencies
├── vendor/               # first-party packages that used to be workspace:*
│   ├── @mavis/           # app modules loaded by the main process
│   ├── @minimax/         # protocol, sandbox runtime, model access
│   └── @earendil-works/  # pi agent packages, patched internal builds
├── resources/mcode-tools # runtime resource the local service loads at startup
├── scripts/
│   ├── setup.sh          # dependencies + Electron runtime + native modules
│   ├── setup-electron.sh # downloads the Electron runtime for this architecture
│   └── rebuild-native.sh # node-gyp rebuild for better-sqlite3 and node-pty
└── run.sh                # starts the app from this tree
```

`node_modules/` and `electron/` are generated by `scripts/setup.sh` and ignored
by git. Downloads and build tooling are cached in
`~/.cache/minimax-code-desktop-src`, outside the repository.

`app/dist` is not minified away: modules keep their names, so a stack trace or a
log line points at a readable file. The renderer in `app/out` is a production
build; edit the UI by rebuilding it from the original project, not by patching the
generated chunks.

## Requirements

- Node.js 22 or newer, npm
- `g++`, `make`, `python3` for `node-gyp`
- `curl`, `unzip`
- A desktop session; Linux arm64 or x64 must match the machine you build on

On Debian/Ubuntu:

```bash
sudo apt install nodejs npm build-essential python3 curl unzip
```

## Build and run

```bash
cd desktop-src
./scripts/setup.sh   # npm ci, Electron download, native rebuild
./run.sh
```

`setup.sh` is idempotent: it runs `npm ci` at the workspace root, reuses cached
archives, and rebuilds the native modules against the Electron ABI. It installs
production dependencies only, because some vendored packages declare native
`devDependencies` (such as `canvas`) that the app never loads.

Environment overrides:

| Variable | Default | Purpose |
| --- | --- | --- |
| `ELECTRON_VERSION` | `42.11.16` | Electron release the native modules are compiled for |
| `NPM_REGISTRY` | `https://registry.npmmirror.com` | registry for npm |
| `ELECTRON_MIRROR` | `https://cdn.npmmirror.com/binaries` | Electron zip and headers mirror |

Changing `ELECTRON_VERSION` requires a matching `package.json` `engines` value and
a rerun of `scripts/setup.sh`.

## What was changed for Linux

- Dependencies that were `workspace:*` in the original monorepo point at
  `vendor/` through `file:` references; `package.json` at the top of this
  directory makes them npm workspaces, so one install resolves both the app and
  every vendored package into `node_modules/`.
- Versions that shipped inside the desktop bundle are pinned exactly, so the tree
  installs the same releases instead of resolving newer ones. The
  `@earendil-works/pi-*` packages are copied from the bundle: the published
  releases lack subpath exports (`./messages`, `./tools`) that the app imports.
- Windows-only binary packages moved to `optionalDependencies`; npm skips them on
  Linux and installs the `-linux-<arch>-gnu` variants declared by each package.
- `better-sqlite3` and `node-pty` are recompiled against the Electron ABI.
- `run.sh` exports `ELECTRON_FORCE_IS_PACKAGED=true`. Electron reports
  `app.isPackaged === false` for an app started from a directory, and the desktop
  UI then looks for source-checkout helpers that are not part of this tree, which
  breaks the local service with `utility runtime initialization handshake failed`.
- `run.sh` also exports `MAVIS_SQLITE3_MODULE_PATH` and `NODE_PATH`. Without them
  the runtime copies `better-sqlite3` into `~/.config` and calls
  `prebuild-install`; with them it loads the module that `rebuild-native.sh`
  already compiled.

## Editing notes

- Main process code lives in `app/dist/main`; one directory per feature, with the
  entry point in `app/dist/main/index.js`.
- `vendor/@mavis/*`, `vendor/@minimax/*` and `vendor/@earendil-works/*` are the
  packages the main process loads at runtime. They are plain source, not bundled.
- After changing anything under `app/dist` or `vendor`, restart `./run.sh`; no
  build step is involved.
- Logs and application data live in `~/.config/MiniMax` and `~/.minimax`.

## Known gaps

These parts of the packaged desktop app are Windows payloads and are not part of
this tree, so the related features stay unavailable on Linux:

- `pptx-core` (PowerPoint export) and `computer-use` binaries
- `session-transfer` and `abe-broker` (Windows session handoff)
- Auto-update is disabled for Linux builds.

Packaging back into a `.deb` is handled by `../desktop/build-linux.sh`, which
starts from the official Windows installer. This tree is for development; it is
not the release path.
